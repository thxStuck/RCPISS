## Описание задачи

Участникам предоставляется исходный код `task.py`, который демонстрирует процесс шифрования с помощью алгоритма RSA, и файл `output.txt`, содержащий параметры открытого ключа (модуль $N$ и экспоненту $e$) вместе с шифртекстом $c$. Задача требует обнаружить уязвимость, возникающую из-за отсутствия схемы дополнения (padding) и малого размера сообщения.

---

## Решение

### Шаг 1: Анализ алгоритма

Изучая файл `task.py`, участник видит классическую реализацию «учебного» RSA: текстовое сообщение конвертируется в число $m$ и шифруется по формуле $c \equiv m^e \pmod N$.

Ключевая деталь находится в параметрах: открытый экспонент $e=3$.

### Шаг 2: Поиск уязвимости

При шифровании RSA безопасность гарантируется операцией взятия остатка (модуля). Однако, если сообщение $m$ достаточно короткое, а $e$ маленькое (как в нашем случае, $e=3$), возникает ситуация, при которой $m^3 < N$.

Если $m^3$ меньше модуля $N$, то операция $\pmod N$ никак не изменяет число. Формула превращается в простое возведение в куб: $c = m^3$.

### Шаг 3: Написание эксплойта

Чтобы восстановить исходное сообщение $m$, достаточно извлечь обычный целочисленный кубический корень из шифртекста $c$: $m = \sqrt[3]{c}$.

Так как числа в RSA огромные (тысячи бит), встроенная функция `math.pow(c, 1/3)` в Python не справится из-за потери точности с числами с плавающей точкой. Участник должен использовать либо стороннюю математическую библиотеку `gmpy2` (функция `gmpy2.iroot(c, 3)`), либо реализовать собственный алгоритм бинарного поиска для извлечения кубического корня.

После вычисления кубического корня полученное большое целое число конвертируется обратно в строку (например, с помощью `Crypto.Util.number.long_to_bytes`), открывая флаг.
