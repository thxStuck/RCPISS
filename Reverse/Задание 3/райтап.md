Внутри программы — маленький процессор. Он смотрит на ваш ввод и решает: правильный ключ или нет.

## Райтап (Решение)

### 1. Первичный анализ

Запустив бинарный файл без аргументов, мы видим запрос на ввод флага:

```bash
$ ./rev_task
Enter the flag: 
```

Если ввести флаг неправильной длины, получим сообщение `Wrong length!`. Путем проб и ошибок или анализа бинарника (например, в IDA Pro или Ghidra) можно обнаружить проверку `strlen(input) != 34`. Это означает, что флаг должен быть длиной 34 символа.

Если ввести флаг правильной длины, но неправильный по содержанию, получим `Access Denied!`.

### 2. Анализ Виртуальной Машины (VM)

Основная логика проверки флага находится в функции `run_vm`. Эта функция интерпретирует массив `bytecode`, который представляет собой последовательность опкодов и их аргументов. Структура `VM` содержит регистры (`regs`), указатель программы (`pc`), флаг ошибки (`failed`), сам байткод (`program`) и входные данные (`input`).

Опкоды VM:

*   `OP_HALT (0x00)`: Останавливает выполнение VM.
*   `OP_LOAD_INPUT (0x01) reg, input_idx`: Загружает символ из `input` по индексу `input_idx` в регистр `reg`.
*   `OP_LOAD_CONST (0x02) reg, val`: Загружает константное значение `val` в регистр `reg`.
*   `OP_ADD (0x03) reg1, reg2`: `regs[reg1] = regs[reg1] + regs[reg2]`.
*   `OP_XOR (0x04) reg1, reg2`: `regs[reg1] = regs[reg1] ^ regs[reg2]`.
*   `OP_SUB (0x05) reg1, reg2`: `regs[reg1] = regs[reg1] - regs[reg2]`.
*   `OP_CMP (0x06) reg, target_val`: Сравнивает значение в `regs[reg]` с `target_val`. Если они не равны, устанавливает `vm->failed = 1`.
*   `OP_ROL (0x07) reg, bits`: Выполняет циклический сдвиг влево значения в `regs[reg]` на `bits` позиций. Использует функцию `rotate_left`.

### 3. Реверс-инжиниринг байткода

Байткод представляет собой последовательность инструкций, которые проверяют каждый символ флага. Анализируя байткод, мы можем заметить повторяющийся шаблон для каждого символа. Для каждого символа `i` флага выполняется следующая последовательность операций:

1.  `OP_LOAD_INPUT 0, i`: Загружает `input[i]` в `regs[0]`.
2.  `OP_LOAD_CONST 1, 0x42`: Загружает константу `0x42` в `regs[1]`.
3.  `OP_XOR 0, 1`: Выполняет `regs[0] = regs[0] ^ regs[1]`, т.е. `input[i] ^ 0x42`.
4.  `OP_LOAD_CONST 1, i`: Загружает индекс `i` в `regs[1]`.
5.  `OP_ADD 0, 1`: Выполняет `regs[0] = regs[0] + regs[1]`, т.е. `(input[i] ^ 0x42) + i`.
6.  `OP_ROL 0, 3`: Выполняет циклический сдвиг влево `regs[0]` на 3 бита.
7.  `OP_CMP 0, target_val`: Сравнивает результат с целевым значением `target_val`.

Таким образом, для каждого символа `input[i]` флага, выполняется проверка:

`rotate_left((input[i] ^ 0x42) + i, 3) == target_val`

### 4. Восстановление флага

Чтобы найти флаг, нам нужно инвертировать эту операцию. Для каждого `target_val` из байткода, мы должны выполнить следующие шаги:

1.  Инвертировать `rotate_left(..., 3)`: это `rotate_right(target_val, 3)`. Функция `rotate_right` может быть реализована как `(val >> (n % 8)) | (val << (8 - (n % 8)))`.
2.  Вычесть `i`: `result - i`.
3.  Инвертировать `XOR 0x42`: `result ^ 0x42`.

Напишем небольшой скрипт на Python для автоматического восстановления флага. Для этого нам понадобится извлечь все `target_val` из байткода. Байткод выглядит примерно так (для каждого символа):

`0x01, 0x00, i, 0x02, 0x01, 0x42, 0x04, 0x00, 0x01, 0x02, 0x01, i, 0x03, 0x00, 0x01, 0x07, 0x00, 0x03, 0x06, 0x00, target_val`
